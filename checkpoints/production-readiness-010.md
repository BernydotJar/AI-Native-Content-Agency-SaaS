## Delivered

### Identity and authorization

- individual identity records with `tenant_id`, `subject_id`, `role`, `key_id`, `api_key`, and `active`;
- fixed `viewer`, `operator`, `approver`, and `admin` roles;
- server-derived tenant, subject, role, key ID, permissions, and authentication method;
- permission gates for identity, run read/create, audit read, and Greenlight decisions;
- tenant-level legacy credentials retained only as migration-only administrator identities;
- frontend identity display and updated browser session contract.

### Rotation and session revocation

- overlapping active key IDs for one subject during rotation;
- session persistence of subject, role, key ID, and full credential fingerprint;
- active-key revalidation on every session-authenticated request;
- bearer and derived-session rejection after a key is removed or marked inactive;
- no raw API key, session token, or CSRF value stored in SQLite.

### Durable authentication abuse controls

- rolling SQLite failure records using opaque bucket hashes;
- strict threshold per credential fingerprint;
- separate, higher threshold per network source to detect password spray without letting a few invalid keys block a valid user behind the same ingress;
- `429` responses with `Retry-After`;
- aggregate Prometheus outcomes only: `succeeded`, `failed`, and `rate_limited`;
- explicit `FORWARDED_ALLOW_IPS` passed to Uvicorn so client source is accepted only from configured proxies.

### Deployment contract

- Helm chart and runtime package version `0.6.0`;
- individual identity Secret key required by the production chart;
- legacy tenant Secret key optional and removable;
- Helm guards for identity, SQLite replica count, credential/source thresholds, and rolling window;
- Terraform variables and Helm release values for identity, optional legacy key, both thresholds, window, trusted proxies, and secure cookie behavior;
- Terraform precondition requiring the source threshold to be greater than or equal to the credential threshold;
- K3s agentless validation reads deployment environment by name and verifies Secret references and security values.

### Documentation and architecture

- README identity/RBAC, rotation, proxy trust, and migration guidance;
- expanded `docs/OPERATIONS.md` endpoint permissions, roles, rotation/revocation, abuse controls, proxy trust, sessions, metrics, audit, and limitations;
- ADR 0006 for individual identity, RBAC, key rotation, and durable abuse controls;
- ADR 0001 and ADR 0003 marked as amended;
- implementation audit updated without claiming managed identity, SSO, MFA, or horizontal rate limiting.

## Security boundary

This increment provides application-managed individual identities and RBAC. It does not provide managed IdP integration, SSO, MFA, SCIM/lifecycle provisioning, account recovery, device policy, or external token validation.

The durable rate limiter is correct for the current single-writer SQLite deployment. Horizontal replicas require a shared atomic limiter and PostgreSQL/shared state. Source attribution depends on correct trusted-proxy configuration and complements, rather than replaces, ingress/WAF controls.

All current roles receive `audit:read`; a broader user population may require a narrower audit policy. Subject IDs are visible in tenant-scoped audit events and should be pseudonymous where privacy requirements demand it.

## Cloud Sandbox MCP push defect

`git_push` was exercised after commits were created. It attempted to start a nested Docker daemon to change checkout ownership and failed during iptables/NAT initialization before Git could push. The persistent checkout was corrected to UID/GID `1000:1000`, and Git was verified successfully as the existing workstation user, but the connector-side `git_push` implementation still owns the failing Docker-in-Docker path.

The Cloud Sandbox MCP source repository is not present in this workspace, was not available through the connected GitHub repository search, and two attempted source workspaces resolved to repository-not-found. Therefore the server-side implementation could not be patched from this product workspace. No push occurred.

The required connector correction remains: perform ownership adjustment and Git execution through the already-running workspace container, or directly against the persistent checkout, without initializing Docker-in-Docker.
